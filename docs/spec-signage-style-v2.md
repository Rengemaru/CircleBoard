# サイネージ表示スタイル v2.3（案）

`docs/spec-v2.2.md` §5 に対する変更提案です。**承認されるまでは §5 が正**で、この文書は提案の状態です。

- 根拠: サイネージ検査記録（所見 F-2 〜 F-5）
- 絵: `wireframes/wireframe-signage-v2.html`（実寸比 16:9・6画面）
- 対象: `frontend/src/pages/SignagePage.tsx` のみ。API・DB・他画面は変更しない

---

## 0. なぜ直すのか

§5.3 は「最小フォント 24px（視認距離2〜3m想定）」と定めていて、実装もそれを満たしています（1920×1080 で 25px）。
**満たしていないのは、24px という数字のほうです。**

1080p の 1px が何ミリになるかは画面の対角で倍以上変わります。55型で 25px は 15.9mm、
「視距離3mにつき文字高25mm」の目安に当てると **1.6m まで近づかないと読めません。**

同時に、色にも2つ穴があります。

| | v2.2 | コントラスト比 | 要件 |
|---|---|---|---|
| 補助テキスト | `#5d6474` | **2.69:1** | 4.5:1 以上 |
| 罫線・カード枠 | `#2b2e3c` | **1.18:1** | 3:1 以上 |

比は最も条件の悪い面（グラデーション右下 `#1a1a24` に `white 3%` を重ねた `#21212b`）で算出。
**`#5d6474` が当たっているのは「最終更新 HH:MM」** — 画面が古いことに気づかせるための文字（Issue #48）です。

---

## 1. 決めてほしいこと（これが決まるまで実装に入らない）

文字を遠くから読める大きさにすると、1枚のカードに入る項目が減ります。
**「文字を大きくする」と「項目を減らす」はセットでしか選べません。** 二択です。

### 案A — いまの密度を維持する

- 実装の変更なし。タグも説明も全部載る
- 代わりに **§5.3 の「視認距離2〜3m」を「1.5m」に書き換える**
- 位置づけが「部室に入った人が席から見る画面」から「掲示板として近くで読む画面」に変わる

### 案B — 遠景優先にする（この文書が推す案）

- 最小フォントを 25px → **38.4px**（55型で 2.5m、50型で 2.3m）
- **3〜4件表示のカードからタグを落とす**（高さが足りないため。1件・2件表示では残す）
- §5.3 の視認距離は「2.5m」に確定させる（3m は QR が物理的に入らないので諦める）

`wireframes/wireframe-signage-v2.html` の **S1（案B）と S6（案A）** を並べて見比べてください。

> **推す理由:** サイネージの目的は参加促進（§3）で、そのためには「まず気づかせる」ことが先。
> タグは近づいてから読めれば足ります。実運用とポートフォリオ映えが衝突したら実運用を優先する（CLAUDE.md §0）という原則にも合います。

## 2. 案Bを採る場合に確定する値

### 2.2 文字の大きさ

| ロゴ | 2.1 | **2.4** | 46.1 | 3.0 m |
| 時計 | 3.1 | **3.6** | 69.1 | 4.5 m |
| 残り日数（3〜4件） | 1.9 | **3.2** | 61.4 | 4.0 m |
| タイトル（3〜4件） | 1.4 | **2.5** | 48.0 | 3.1 m |
| 残り日数（2件） | 2.7 | **4.8** | 92.2 | 6.0 m |
| タイトル（2件） | 1.75 | **3.2** | 61.4 | 4.0 m |
| 残り日数（1件） | 5.6 | **7.0** | 134.4 | 8.7 m |
| タイトル（1件） | 3.2 | **3.8** | 73.0 | 4.7 m |
| プロジェクト名 | 1.5 | **2.2** | 42.2 | 2.7 m |

和文のインキ高さを em の 0.85 倍、視距離3mにつき文字高25mm として換算。

### 2.3 QR

| 配置 | v2.2 | v2.3 案 | 55型での実寸 | 読める距離 |
|---|---:|---:|---:|---:|
| 1件（ヒーロー） | 220 px | **320** | 203 mm | 2.0 m |
| 0件表示 | 200 | **300** | 190 | 1.9 m |
| 2件 | 110 | **221** | 140 | 1.4 m |
| 3〜4件 | 110 | **165** | 105 | 1.1 m |
| プロジェクト | 90 | **125** | 79 | 0.8 m |

10:1 則（読み取り距離はコード幅の10倍まで）で算出。

**QRだけは 2〜3m に届きません。** 3m から読めるQRは 300mm（520px 相当）で、カードに入りません。
この案は「**遠くから残り日数とタイトルを読み、気になったら1〜2m まで歩み寄ってQRを読む**」という動線を前提にします。
**この前提を §5.3 に明記することが、案Bの受け入れ条件のひとつです。**

### 2.4 フォント（F-4）

いまサイネージに効いているのは `smarthr-ui.css` の `system-ui` で、**3mから読む画面のために選ばれた指定ではありません。**
Windows では Yu Gothic UI（線が細く遠距離に最も不利）、和文フォントの入っていない Linux 端末では豆腐（□□□）になります。

`SignagePage.tsx` の `Screen` にサイネージ専用で指定します（アプリ本体には影響させない）。

```
font-family: "Noto Sans JP", "Hiragino Sans", "Yu Gothic UI", sans-serif;
font-feature-settings: "palt";   /* wireframe-signage.html にあった詰めの復活 */
font-weight: 500;                /* 既定の 400 のままにしない */
```

Noto Sans JP を同梱するかは別判断です。部室端末をオフラインで運用するなら同梱が要ります。

### 2.5 ゾーンの高さ配分

文字を大きくすると 2×2 のカードが高さ不足になります。余っていたプロジェクト枠から回します。

| | v2.2 | v2.3 案 |
|---|---:|---:|
| `.ev-zone` の flex | 1.35 | **1.75** |
| `.pj-zone` の flex | 1 | 1 |

実測で、v2.2 のプロジェクトカードは1枚あたり 50px の余剰がありました。

### 2.6 プロジェクトカード

- 「予定」と「人数」を **1行にまとめる**（`毎週水曜 18:00〜 ・ 4 / 8名`）
- タイトルは **2行まで**（3列で幅が足りないため。`-webkit-line-clamp: 2`）

## 3. 実装に写すとき

`wireframes/wireframe-signage-v2.html` の **cqw の数値は、そのまま `su(n)` の n になります。**
`su(n)` は 16:9 のとき n vw と等しく、キャンバス幅の n% に一致するためです。

```
.ec.c4 .ec-cd{font-size:3.2cqw}  →  COUNTDOWN_SIZE.compact = su(3.2)
```

---

## 4. 受け入れ条件

1. 1920×1080 で `wireframes/wireframe-signage-v2.html` の S1〜S5 と見た目が一致する
2. **表示件数 0〜4件 × 主要な解像度で、カードのはみ出しが 0 であること**（PR #217 の検査と同じ基準）
3. `npm run lint` と `npm run typecheck` が通る
4. 補助テキストと罫線のコントラスト比が、最も条件の悪い面で 4.5:1 / 3:1 を満たす

## 5. スコープ外

- 縦置き（9:16）レイアウト — 重なりは出ないが余白が大きい。別Issue
- 焼き付き対策（ピクセルシフト） — 別Issue
- `su()` の下限（`max(24px, …)`） — 小さい窓で今度ははみ出すため、単独では決められない
- QRを 3m 対応にすること — カードに入らないので不可能
- アプリ本体（`/events` 等）の配色・文字サイズ
