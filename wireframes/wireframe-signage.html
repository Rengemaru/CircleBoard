データ取得は1リクエストのみ。GET /api/signage?token=xxx で spotlight_events と projects を同時に返す。 60秒ごとに叩かれるため、リクエスト数を最小化する。
イベント = 黄（#fcd34d）／プロジェクト = 青（#5eb3f5）。 2つのカテゴリの違いを、遠くからでも色だけで判別できるようにする。カウントダウンは黄のみに使い、 プロジェクト側には使わない（プロジェクトに締切の概念がないため）。
owner（企画者名）と participants（参加者一覧）は表示しない。 サイネージは current_user が nil の状態なので、EventSerializer に current_user: nil を渡せば自動的に落ちる。 サイネージ専用のシリアライザを新設しないこと（出し分けが二重管理になり、片方だけ塞ぎ忘れる事故につながる）。

SP実装仕様まとめ

レイアウトの分岐

対象イベント数グリッドカウントダウンタイトル
0件空状態レイアウト（S4）——
1件1fr（ヒーロー）5.6cqw3.2cqw
2件1fr 1fr2.7cqw1.75cqw
3〜4件1fr 1fr / 1fr 1fr2.7cqw1.75cqw
5件以上上位4件のみ表示2.7cqw1.75cqw
プロジェクトも同様に可変（最大6枠 / 3列）。いずれの場合も空枠を描画しない。

共通仕様

解像度1920×1080（16:9）
背景linear-gradient(135deg, #0f0f15, #1a1a24)
最小フォント24px 相当（視認距離2〜3m）
リロード60秒ごとに window.location.reload()。WebSocketは不採用
時計クライアント側 setInterval で毎秒更新（リロードとは独立）
ナビゲーションなし。ヘッダー・フッター・リンクを一切表示しない
認証?token=。無効・失効は 404（401ではない）
レート制限同一IPから30回/分（rack-attack）
端末設定Chrome キオスクモード chrome --kiosk "https://…/signage?token=…"

QRコード

生成場所フロントエンド（qrcode.react）。サーバー生成だと60秒ごとに無駄な処理が走る
中身各企画の詳細ページURL
URLの組み立てサーバー側で ENV['PUBLIC_BASE_URL'] から作り、detail_url として返す
URLをフロントで組み立てないのは、サイネージ端末側の設定に依存させないため。 端末はURLを開くだけの存在にしておくと、ドメイン変更時にサーバーの環境変数1つで済む。

表示対象の抽出ルール

並び順除外
イベント ピン留め1件を先頭固定 → 残りを spotlight_score 降順 starts_at が過去 / completed / trashed
プロジェクト recruiting → in_progress completed / trashed
プロジェクトに注目スコアは使わない。プロジェクトには「開催日」がなく締切感が存在しないため、 スコアの主成分（開催間近ボーナス）が機能しない。ステータス順が設計として正しい。
